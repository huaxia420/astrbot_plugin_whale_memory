# 鲸忆 · astrbot_plugin_whale_memory

给 AstrBot 一套真正的长期记忆。原来她只有 20 条群消息的滚动窗口，聊完就忘。

## 它做什么

三层结构：

1. **记录**：每一轮对话（用户说的 / 她回的）落到本地 sqlite，jieba 分词 + 中文二元组建 FTS5 索引
2. **压缩**：每天凌晨把前一天的对话压成一段 150–250 字日记，长期事实靠这层扛
3. **回想**：每次生成回复前，按当前话题检索相关旧事，以临时内容块注入——不改 system prompt，不破坏上下文缓存

## 指令

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `/记 内容` | 让她明确记住一件事 | 所有人 |
| `/回忆 关键词` | 翻旧账 | 所有人 |
| `/记忆状态` | 看条数与最早记录 | 所有人 |
| `/忘记 关键词` | 删掉含关键词的记忆 | 管理员 |

## 配置

全在 WebUI 插件设置里，常用几项：

- `inject_count`：每次注入几条，默认 5，建议不超过 8
- `inject_max_chars`：注入字数上限，默认 800
- `digest_hour`：日记生成时间，默认 3 点
- `retention_days`：原始对话保留天数，默认 180，设 0 为永久

## 设计取舍

- **按 scope 隔离**：`group:<群号>` / `friend:<QQ>`，A 群的记忆 B 群看不到
- **不注入就不花额度**：消息太短（默认 < 4 字）直接跳过检索
- **不做向量检索**：jieba + 二元组 + FTS5 已经够日常用，省一个 embedding 依赖

## 依赖

无外部依赖。容器内自带 jieba、sqlite3（含 FTS5）。

## 文件

- 数据库：`data/plugin_data/astrbot_plugin_whale_memory/memory.db`
- 备份直接复制这个文件即可（先 `docker stop astrbot`）

## 已知限制

- 图片、语音消息只记文字部分，不解码内容
- 跨群不共享记忆（有意为之）
- 日记需要 LLM 生成，会消耗少量额度；关掉 `digest_enable` 可停
